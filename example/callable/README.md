# NativeCallable.listener latency benchmark

The Dart build hook invokes xmake and provides the resulting native code asset,
so no manual native build or hard-coded `.so` path is needed:

```sh
dart run bin/callable.dart --hz=1000 --seconds=3
dart run bin/callable.dart --hz=1000 --seconds=3 --busy-ms=5
```

Native timestamps immediately before invoking the listener. Dart reads the
same C++ `steady_clock`, avoiding mismatched clock epochs.

## Measurement

The native worker records `t1` immediately before calling
`NativeCallable.listener`. The callback is then posted to the Dart isolate's
event queue. When the Dart callback actually starts, it records `t2`:

```text
native thread: t1 -> listener()
                         |
                         v
Dart isolate:       event queue -> callback: t2
```

Each dispatch latency sample is `t2 - t1`. Both timestamps come from the same
C++ `steady_clock`, so wall-clock adjustments and mismatched clock epochs do
not affect the result. Repeating this at different native frequencies and Dart
loads reveals typical latency, tail latency, and whether callbacks accumulate
in the event queue.

```dart
// c
void c_thread() {
    final t1 = now();
    dart_callback(t1);
}
// dart
final callback = (t1) {
    final t2 = now();
    final delta = t2 - t1;
}
```


## Results

The following measurements were collected on `TSJ20010049-L` at 1 kHz for
three seconds (3,000 callbacks per run).

| Dart isolate load | Throughput | Min | Average | P50 | P90 | P99 | P99.9 | Max | First 10% avg | Last 10% avg |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Idle | 996.9/s | 7.4 us | 28.1 us | 24.4 us | 33.9 us | 72.3 us | 95.6 us | 3,026.2 us | 43.3 us | 24.6 us |
| Busy 5 ms every 10 ms | 997.4/s | 5.7 us | 1,343.9 us | 619.1 us | 4,597.0 us | 4,702.2 us | 4,797.8 us | 6,556.2 us | 1,384.2 us | 1,329.0 us |

In the idle run, the typical dispatch latency was tens of microseconds, but a
single 3.03 ms outlier still occurred. When the receiving isolate was occupied
for 5 ms every 10 ms, throughput remained close to 1 kHz while average latency
rose to 1.34 ms and P99 rose to 4.70 ms. The similar first/last 10% averages in
the busy run show no continuously growing backlog during this three-second
sample, but the result also demonstrates that `NativeCallable.listener` does
not provide deterministic real-time latency when the Dart isolate is busy.

## Layout

- `include/`: public C ABI
- `src/`: C++ implementation
- `lib/src/binding/`: bindings generated by ffigen
- `lib/src/benchmark.dart`: Dart benchmark API
- `hook/build.dart`: xmake code-asset build hook
- `tool/ffigen.dart`: binding generator

Regenerate bindings after changing the public header:

```sh
dart run tool/ffigen.dart
```
